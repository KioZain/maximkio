# Как работать с переводом

Тексты сайта живут не в разметке, а в словарях `src/locales/ru.json` и
`src/locales/en.json`. Шаблон обращается к ним по ключу, а webpack на сборке
прогоняет каждую переводимую страницу через каждый язык:

```
src/index.html + ru.json  →  docs/index.html
src/index.html + en.json  →  docs/en/index.html
```

Русский лежит в корне, английский — в `/en/`. У каждой версии свой URL,
готовая разметка в исходнике и правильный `lang` — ссылку можно отправить
человеку и её же увидит поисковик.

## Карта файлов

| Файл | Зачем |
| --- | --- |
| `src/locales/ru.json` | тексты, эталон: ключи заводятся здесь |
| `src/locales/en.json` | те же ключи, английские значения |
| `config/i18n/config.js` | список языков и страниц — единственное место, где они описаны |
| `config/i18n/render.js` | движок подстановки: `{{ }}`, `{{{ }}}`, `{{#each}}` |
| `config/i18n/loader.js` | webpack-загрузчик: кладёт словарь в шаблон, считает `site.*` |
| `config/webpack.pages.js` | собирает HtmlWebpackPlugin по списку страница × язык |

## Перевести очередной кусок текста

1. **Найти строку в шаблоне.** Например, заголовок секции «Опыт работы»
   в `src/index.html`.
2. **Перенести её в `ru.json`** — ровно как есть, вместе с неразрывными
   пробелами и кавычками-ёлочками. Копировать, а не перенабирать: в текстах
   уже стоят `&nbsp;` после коротких предлогов, на глаз они неотличимы
   от обычных пробелов.
3. **Тот же ключ добавить в `en.json`** с переводом. Ключ должен появиться
   в обоих файлах сразу — иначе английская сборка упадёт.
4. **В шаблоне поставить `{{ ключ }}`** вместо текста.
5. **Собрать** (`npm run build`) и посмотреть обе версии.

Ключ называется по месту, а не по тексту: `work.title`, а не
`work.opyt_raboty`. Когда заголовок сменится, ключ останется прежним.
Первый уровень ключа совпадает с блоком вёрстки (`hero`, `header`, `work`),
глубина — не больше трёх уровней.

## Три конструкции в шаблоне

```html
{{ hero.status }}          <!-- обычный текст, спецсимволы экранируются -->
{{{ hero.note }}}          <!-- строка вставляется как есть, вместе с разметкой -->

{{#each site.languages}}   <!-- повтор блока по массиву из словаря -->
  <a href="{{ url }}">{{ label }}</a>
{{/each}}
```

Внутри `{{#each}}` ключи ищутся сначала в элементе массива, потом снаружи —
так что `{{ hero.name }}` внутри цикла тоже работает.

Тройные скобки нужны редко. Если внутри строки понадобилась разметка — сначала
подумайте, не проще ли разбить её на два ключа и оставить теги в шаблоне.
Так сделано с подчёркнутой фразой в первом экране: `<span id="underline">`
живёт в разметке, а в словаре лежат отдельно `hero.leadIn` и `hero.bio`.

## Что подставляется само

Кроме словаря шаблону доступны два служебных имени — их нельзя использовать
как ключи в JSON:

| Переменная | Что внутри |
| --- | --- |
| `{{ site.lang }}` | код текущего языка, для атрибута `lang` |
| `{{ site.languages }}` | массив всех версий страницы: `code`, `label`, `short`, `url`, `ariaCurrent` |
| `{{ site.current.short }}` | подпись текущего языка на кнопке переключателя |
| `{{ site.other.url }}` | ссылка на версию на другом языке |
| `{{ site.default.url }}` | ссылка на версию на языке по умолчанию — для `hreflang="x-default"` |
| `{{ site.root }}` | путь от страницы к корню сайта; ставится перед внутренними ссылками |
| `{{ page.title }}`, `{{ page.description }}` | meta текущей страницы из `pages.<id>` в словаре |

**Внутренние ссылки всегда пишутся через `{{ site.root }}`:**

```html
<a href="{{ site.root }}pages/cases/artovoe.html">
```

Из русской версии получится `pages/…`, из английской — `../pages/…`.
Без этого ссылка со страницы в `/en/` уедет в никуда.

## Добавить переводимую страницу

Пока у страницы в `config/i18n/config.js` нет флага `i18n: true`, она
собирается только по-русски и в `/en/` не попадает. Это сделано намеренно:
на сайте не появляется английский адрес с русским текстом внутри.

Порядок такой:

1. вынести тексты страницы в словари, как описано выше;
2. добавить `pages.<id>` с `title` и `description` в оба словаря;
3. поставить `i18n: true` у страницы в `config.js`.

## Добавить язык

В `config/i18n/config.js` дописать язык в `LANGUAGES`
(`code`, `dir`, `label`, `short`) и создать `src/locales/<code>.json`
со всеми ключами. Переключатель, `hreflang` и адреса страниц соберутся сами —
они строятся по этому списку.

Первый язык в списке — язык по умолчанию, он живёт в корне. Менять порядок
после публикации не стоит: это переезд всех URL.

## Когда сборка падает

Движок специально не прощает пропусков — лучше сломанный билд, чем страница
со словом `undefined` в заголовке.

```
[i18n] ключ "hero.status" не найден в словаре
  шаблон: ./src/index.html
  язык:   en
```

Читается буквально: в `en.json` нет ключа, который есть в шаблоне. Другие
частые сообщения — «указывает на объект» (ключ ведёт на ветку, а не на строку)
и «зарезервированы движком» (в словаре появился ключ `site` или `page`).

Проверить, что наборы ключей в словарях совпали:

```bash
node -e "const r=require('./src/locales/ru.json'),e=require('./src/locales/en.json');const k=(o,p='')=>Object.entries(o).flatMap(([a,v])=>v&&typeof v==='object'?k(v,p+a+'.'):[p+a]);const R=k(r),E=k(e);console.log('только в ru:',R.filter(x=>!E.includes(x)));console.log('только в en:',E.filter(x=>!R.includes(x)))"
```

## Что стоит помнить

- **Русский — эталон.** Ключ сначала появляется в `ru.json`, потом в `en.json`.
  Так не бывает ключей, существующих только в переводе.
- **Пустая строка — законное значение,** отсутствующий ключ — нет. Если фразы
  на английском пока не будет, оставьте `""`, а не удаляйте ключ.
- **`&` и кавычки экранируются сами.** Писать `&amp;` в словаре не нужно —
  получится `&amp;amp;`.
- **Периоды и даты — тоже текст.** «Сентябрь — Декабрь 2025» переводится.
- **Партиал `src/partials/footerbar.html` через словари пока не проходит:**
  его подключает отдельный плагин, до i18n-загрузчика дело не доходит.
  Текст футера остаётся русским, пока это не переделано.
- **Магия ограничена тремя конструкциями.** Логики в шаблоне нет: если нужен
  другой текст — это другой ключ, а не условие.
