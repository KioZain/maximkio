# Как работать с переводом

Тексты сайта живут не в разметке, а в словарях `src/locales/ru.json` и
`src/locales/en.json`. Шаблон обращается к ним по ключу, а webpack на сборке
прогоняет каждую переводимую страницу через каждый язык:

```
src/index.html + ru.json  →  docs/index.html
src/index.html + en.json  →  docs/en/index.html
```

Русский лежит в корне, английский — в `/en/`. У каждой версии свой URL,
готовая разметка в исходнике и правильный `lang` — ссылку можно отправить
человеку и её же увидит поисковик.

## Карта файлов

| Файл | Зачем |
| --- | --- |
| `src/locales/ru.json` | тексты, эталон: ключи заводятся здесь |
| `src/locales/en.json` | те же ключи, английские значения |
| `config/i18n/config.js` | список языков и страниц — единственное место, где они описаны |
| `config/i18n/render.js` | движок подстановки: `{{ }}`, `{{{ }}}`, `{{#each}}`, `{{> }}`, `{{#blocks}}` |
| `config/i18n/loader.js` | webpack-загрузчик: кладёт словарь в шаблон, считает `site.*` |
| `src/content/**.json` | структура страниц, собираемых из блоков (порядок и состав) |
| `src/partials/case/*.html` | разметка одного типа блока — по файлу на тип |
| `config/webpack.pages.js` | собирает HtmlWebpackPlugin по списку страница × язык |

## Перевести очередной кусок текста

1. **Найти строку в шаблоне.** Например, заголовок секции «Опыт работы»
   в `src/index.html`.
2. **Перенести её в `ru.json`** — ровно как есть, вместе с неразрывными
   пробелами и кавычками-ёлочками. Копировать, а не перенабирать: в текстах
   уже стоят `&nbsp;` после коротких предлогов, на глаз они неотличимы
   от обычных пробелов.
3. **Тот же ключ добавить в `en.json`** с переводом. Ключ должен появиться
   в обоих файлах сразу — иначе английская сборка упадёт.
4. **В шаблоне поставить `{{ ключ }}`** вместо текста.
5. **Собрать** (`npm run build`) и посмотреть обе версии.

Ключ называется по месту, а не по тексту: `work.title`, а не
`work.opyt_raboty`. Когда заголовок сменится, ключ останется прежним.
Первый уровень ключа совпадает с блоком вёрстки (`hero`, `header`, `work`),
глубина — не больше трёх уровней.

## Конструкции в шаблоне

```html
{{ hero.status }}          <!-- обычный текст, спецсимволы экранируются -->
{{{ hero.note }}}          <!-- строка вставляется как есть, вместе с разметкой -->

{{#each site.languages}}   <!-- повтор блока по массиву из словаря -->
  <a href="{{ url }}">{{ label }}</a>
{{/each}}

{{> headerbar }}           <!-- сюда встаёт src/partials/headerbar.html -->

{{#blocks data.blocks from case}}
                           <!-- страница собирается из блоков, см. ниже -->
```

Внутри `{{#each}}` ключи ищутся сначала в элементе массива, потом снаружи —
так что `{{ hero.name }}` внутри цикла тоже работает.

Куски вставляются до подстановки текстов, поэтому `{{> }}` спокойно стоит
внутри `{{#each}}`: сначала на месте тега окажется разметка, потом движок
повторит её по массиву. Так собран список мест работы на главной —
`{{#each work.items}} {{> list/job }} {{/each}}`.

Движок не знает про HTML-комментарии: скобки внутри `<!-- -->` он выполнит
наравне с остальными. Описывая в комментарии конструкцию, пишите её словами
(«цикл по work.items»), иначе сборка упадёт на несуществующем `{{/each}}`.

Тройные скобки нужны редко. Если внутри строки понадобилась разметка — сначала
подумайте, не проще ли разбить её на два ключа и оставить теги в шаблоне.
Так сделано с подчёркнутой фразой в первом экране: `<span id="underline">`
живёт в разметке, а в словаре лежат отдельно `hero.leadIn` и `hero.bio`.

## Что подставляется само

Кроме словаря шаблону доступны два служебных имени — их нельзя использовать
как ключи в JSON:

| Переменная | Что внутри |
| --- | --- |
| `{{ site.lang }}` | код текущего языка, для атрибута `lang` |
| `{{ site.languages }}` | массив всех версий страницы: `code`, `label`, `short`, `url`, `ariaCurrent` |
| `{{ site.current.short }}` | подпись текущего языка на кнопке переключателя |
| `{{ site.other.url }}` | ссылка на версию на другом языке |
| `{{ site.default.url }}` | ссылка на версию на языке по умолчанию — для `hreflang="x-default"` |
| `{{ site.root }}` | путь от страницы к корню сайта; ставится перед внутренними ссылками |
| `{{ page.title }}`, `{{ page.description }}` | meta текущей страницы из `pages.<id>` в словаре |
| `{{ page.image }}` | полный адрес картинки превью, из `pages.<id>.image` |
| `{{ site.url }}` | полный адрес текущей страницы — для canonical и og:url |
| `{{ site.origin }}` | адрес сайта с доменом, задан в `config.js` |
| `{{ site.name }}` | имя сайта для `og:site_name` — заголовок главной |
| `{{ site.locale }}` | код для `og:locale` (`ru_RU`) |
| `{{ data.* }}` | структура страницы из файла, указанного в `data` (только у страниц из блоков) |

Ключ `content` в словаре тоже служебный, но с другой стороны: его не движок
подставляет, а движок в нём ищет — там лежат тексты блоков, см. ниже.

**Внутренние ссылки всегда пишутся через `{{ site.root }}`:**

```html
<a href="{{ site.root }}pages/cases/artovoe.html">
```

Из русской версии получится `pages/…`, из английской — `../pages/…`.
Без этого ссылка со страницы в `/en/` уедет в никуда.

Два исключения, о которые легко споткнуться:

- **Ссылка на переведённую страницу пишется обычным относительным путём.**
  Дерево `/en/` зеркалит корень, поэтому `href="../../index.html"` из кейса
  ведёт на главную того же языка — а `{{ site.root }}index.html` увёл бы
  англоязычного читателя на русскую главную.
- **`{{ site.root }}` нельзя ставить в `src` картинок.** Адреса картинок
  считает html-loader, и считает он их от файла шаблона, а не от готовой
  страницы: у русской и английской версии шаблон один и тот же, а
  `site.root` — разный. Английская сборка просто не найдёт файл. В `src`
  всегда обычный относительный путь.

## Метатеги и превью ссылки

Весь служебный `<head>` лежит в одном куске — `src/partials/meta.html`, и
подключается одной строкой:

```html
{{> meta }}
```

Там `title`, `description`, `canonical`, языковые альтернативы и карточка
опенграфа. Один файл на все переводимые страницы намеренно: набор тегов
иначе расходится от страницы к странице, а замечается это только после
того, как ссылку уже кому-то отправили.

Иконка сайта в этот кусок не входит — путь к ней относительный, а страницы
лежат на разной глубине. Всё, что внутри, от глубины не зависит: адреса либо
абсолютные, либо их нет.

### Почему адреса абсолютные

`canonical`, `hreflang` и `og:image` читает не браузер, а краулер — поисковика
или мессенджера, — и разворачивает их вне контекста страницы. Относительный
путь ему разворачивать не от чего. Поэтому в `config/i18n/config.js` задан
`ORIGIN`, адрес сайта с доменом, и из него строятся `site.url` и `page.image`.

**Сменился домен — меняется одна строка в `config.js`.**

### Картинка превью

Лежит в `src/og/`, размер 1200×630, формат JPEG. Копируется в сборку как
есть, под своим именем — без хэша: адрес уходит наружу и кэшируется на
стороне мессенджера, поэтому должен быть стабильным. Отсюда же и отдельный
`CopyPlugin` в `webpack.common.js`: обычное правило ассетов имя хэширует.

Какой файл у какой страницы — в словаре, `pages.<id>.image`. Ключ обязателен:
без него сборка падает, а не отдаёт ссылку в никуда. Картинка, одинаковая
для обоих языков, пишется в оба словаря одним значением.

Подробности про имена — в `src/og/README.md`.

## Страница из блоков

Кейс — это не разметка, а список блоков. Три файла, и каждый не знает про
два других:

| Где | Что там |
| --- | --- |
| `src/content/cases/<кейс>.json` | порядок и состав блоков, картинки, размеры |
| `src/partials/case/<тип>.html` | как выглядит блок этого типа — один файл на тип |
| `src/locales/*.json` → `content["cases/<кейс>"]` | тексты блоков, по одному ключу на блок |

Шаблон страницы разворачивает всё это одной строкой:

```html
{{#blocks data.blocks from case}}
```

Читается так: пройти по массиву `data.blocks` и для каждого элемента взять
кусок разметки из `src/partials/case/<type>.html`. Закрывающего тега нет —
тело приходит из файла, а не из шаблона.

### Из чего состоит блок

```json
{ "type": "picture", "id": "example", "width": 756, "height": 429 }
```

Два поля обязательны:

- **`type`** — какой кусок разметки подставить;
- **`id`** — под каким ключом лежат тексты блока в словаре.

Остальные поля — что угодно, чем пользуется кусок разметки. Внутри куска
доступны поля самого блока (`{{ width }}`), его тексты (`{{ text.image }}`,
`{{ text.caption }}`) и всё, что снаружи (`{{ site.root }}`, словарь целиком).

Тексты того же блока в обоих словарях:

```json
"content": {
  "cases/artovoe": {
    "example": { "caption": "Подпись к картинке", "alt": "" }
  }
}
```

**`id` — не индекс.** Ключ текста привязан к `id`, поэтому блоки можно
переставлять и удалять, не трогая словари. Именно поэтому же `id` не стоит
переименовывать просто так: это переезд ключей в двух файлах.

### Оглавление собирается само

Меню кейса не пишется руками. В него попадает каждый блок, у которого в
словаре есть `title` — то есть ровно тот, что рисует `<h3>`:

```html
<nav class="O_NavMenu">
  <ul>
    {{#each page.headings}}
    <li><a class="{{ className }}" href="#{{ id }}">{{ title }}</a></li>
    {{/each}}
  </ul>
</nav>
```

Цитаты и картинки заголовка не имеют и не попадают в меню сами собой, без
списка исключений. Обратная сторона того же правила: **назвал заголовок блока
`title` — блок появится в оглавлении.** Нужен заголовок, которого в меню быть
не должно, — назовите ключ иначе (`caption`, `lead`, `heading`).

Подпись пункта можно задать отдельно — ключом `navTitle` рядом с `title`:

```json
"webposter": {
  "title": "Интерактивный учебник веб-плаката по основам веб-верстки",
  "navTitle": "О проекте"
}
```

На странице остаётся `title`, в меню уходит `navTitle`. Нужно это там, где
заголовок длинный: целое название проекта в узкой колонке меню не живёт.
На попадание в оглавление `navTitle` не влияет — блок без `title` в меню не
идёт, сколько бы подписей ему ни завели.

Обратная задача — заголовок на странице есть, а пункта в меню быть не должно.
Это `"nav": false` в структуре кейса:

```json
{ "type": "prose", "id": "idea", "nav": false }
```

Нужно для ремарок и приложений, по которым никто не прыгает: в длинном кейсе
меню иначе занимает полэкрана. Заголовок остаётся на месте, ссылка по якорю
продолжает работать, подсветка текущего раздела не ломается — `navSpy` берёт
цели из самих ссылок меню, поэтому пока читатель внутри скрытой секции,
подсвеченным остаётся предыдущий пункт.

Флаг живёт в JSON, а не в словаре: на обоих языках оглавление должно быть
одним и тем же.

Пункты считаются на сборке и лежат прямо в исходнике страницы: меню видно
сразу, до всякого JS и без него. Первый пункт помечен активным там же.
Дальше по ходу прокрутки класс переставляет чанк `navSpy` — его нужно
добавить в `chunks` страницы.

### Что где живёт

Правило простое: **в JSON — то, что не переводится.** Размеры, соотношения,
адреса внешних ссылок. Всё, что меняется от языка, — в словаре.

**Картинки — в словаре, а не в JSON.** Скриншот интерфейса с русскими
надписями и он же с английскими — это две разные картинки, то есть ровно то,
что переводится. Поэтому путь лежит рядом с подписью и `alt`:

```json
"filters": {
  "image": "webposter/filters-ru",
  "caption": "Фильтры помогают быстро подобрать референсы",
  "alt": ""
}
```

Картинка, одинаковая для обоих языков, просто записывается в оба словаря
одним и тем же значением — повтор здесь честнее флага «не переводить»:
видно, какой файл уйдёт на каждом языке, и в любой момент можно развести их,
не трогая ни разметку, ни структуру блоков.

Так же устроены карточки проектов на главной — `projects.items[].cover` лежит
в словаре с самого начала.

Пути пишутся **от `src/images/` и без расширения**: `"artovoe/cover"`, а не
`"../../images/artovoe/cover.png"`. И префикс, и формат знает кусок разметки,
и только он.

В JSON у блока с картинкой остаются только `type`, `id` и размер слота:

```json
{ "type": "picture", "id": "filters", "width": 756, "height": 425 }
```

Размер — не свойство файла, а свойство места в вёрстке, и от языка он не
зависит: русский и английский скриншот снимаются с одного и того же экрана.

Без расширения — потому что из одного пути собирается несколько адресов:
avif и webp, каждый в двух плотностях. Эти файлы делает `npm run images` из
мастера в `src/images/**`, кладёт в `src/images/derived/**` и больше их никто
руками не трогает. Подробности и размеры слотов — в `scripts/images.mjs`.

Мастер наружу не отдаётся вовсе: в сборку уезжают только производные.

### Условий нет

В движке нет `{{#if}}`, и в блоках он тоже не появится. Нужна картинка,
которая не раскрывается в лайтбокс, — это отдельный `type`, а не флаг в
данных. Так набор блоков остаётся обозримым: сколько файлов в
`src/partials/case/`, столько на сайте и бывает блоков.

### Завести новый кейс

0. мастера картинок в `src/images/<кейс>/` и `npm run images`;
1. `src/content/cases/<кейс>.json` — список блоков;
2. `content["cases/<кейс>"]` в **обоих** словарях — тексты;
3. `pages["cases/<кейс>"]` в обоих словарях — title и description;
4. страница в `src/pages/cases/` — шапка, `{{#each page.headings}}`, `{{#blocks}}`;
5. запись в `PAGES` (`config/i18n/config.js`) с `data`, `chunks` и `i18n: true`.

### Какие типы блоков есть сейчас

| Тип | Что рисует | Тексты |
| --- | --- | --- |
| `intro` | обложка, теги, заголовок, лид, таблица фактов | `cover`, `title`, `navTitle`, `lead`, `coverAlt`, `tags[]`, `facts[]` |
| `text` | заголовок и один абзац | `title`, `body` |
| `prose` | заголовок и несколько абзацев | `title`, `paragraphs[].line` |
| `para` | абзацы без заголовка | `paragraphs[].line` |
| `list` | заголовок и нумерованный список | `title`, `items[].line` |
| `points` | нумерованные карточки без заголовка | `items[].line` |
| `quote` | цитата с портретом автора | `portrait`, `quote`, `name`, `role`, `portraitAlt` |
| `picture` | картинка с подписью, раскрывается в лайтбокс | `image`, `caption`, `alt` |
| `video` | короткий ролик вместо гифки, играется сам | `video`, `caption`, `label` |
| `stats` | плитки с цифрами | `items[].value`, `items[].label` |
| `link` | кнопка-ссылка на внешний ресурс | `label` |

В оглавление кейса попадают только те, у которых в словаре есть `title`:
`intro`, `text`, `prose`, `list`. Остальные идут продолжением предыдущего
блока — поэтому у `para`, `points` и `stats` заголовка нет вовсе.

### Завести новый тип блока

Файл в `src/partials/case/`. Имя файла — это и есть `type`. Больше нигде
регистрировать не нужно: движок ищет кусок по имени и падает, если не нашёл.

### Когда падает сборка блоков

```
[i18n] ключ "text.title" не найден в словаре
  шаблон: ./src/pages/cases/artovoe.html → блок "context" (case/text.html)
  язык:   en
  тексты: content["cases/artovoe"].context в src/locales/en.json
```

Последняя строка — адрес, куда класть ключ. Другие сообщения того же рода:
«нет куска разметки case/paragraph.html» (опечатка в `type`), «у блока
data.blocks[4] нет "id"».

## Добавить переводимую страницу

Пока у страницы в `config/i18n/config.js` нет флага `i18n: true`, она
собирается только по-русски и в `/en/` не попадает. Это сделано намеренно:
на сайте не появляется английский адрес с русским текстом внутри.

Порядок такой:

1. вынести тексты страницы в словари, как описано выше;
2. добавить `pages.<id>` с `title` и `description` в оба словаря;
3. поставить `i18n: true` у страницы в `config.js`.

## Добавить язык

В `config/i18n/config.js` дописать язык в `LANGUAGES`
(`code`, `dir`, `label`, `short`) и создать `src/locales/<code>.json`
со всеми ключами. Переключатель, `hreflang` и адреса страниц соберутся сами —
они строятся по этому списку.

Первый язык в списке — язык по умолчанию, он живёт в корне. Менять порядок
после публикации не стоит: это переезд всех URL.

## Когда сборка падает

Движок специально не прощает пропусков — лучше сломанный билд, чем страница
со словом `undefined` в заголовке.

```
[i18n] ключ "hero.status" не найден в словаре
  шаблон: ./src/index.html
  язык:   en
```

Читается буквально: в `en.json` нет ключа, который есть в шаблоне. Другие
частые сообщения — «указывает на объект» (ключ ведёт на ветку, а не на строку)
и «зарезервированы движком» (в словаре появился ключ `site` или `page`).

Проверить, что наборы ключей в словарях совпали:

```bash
node -e "const r=require('./src/locales/ru.json'),e=require('./src/locales/en.json');const k=(o,p='')=>Object.entries(o).flatMap(([a,v])=>v&&typeof v==='object'?k(v,p+a+'.'):[p+a]);const R=k(r),E=k(e);console.log('только в ru:',R.filter(x=>!E.includes(x)));console.log('только в en:',E.filter(x=>!R.includes(x)))"
```

## Что стоит помнить

- **Русский — эталон.** Ключ сначала появляется в `ru.json`, потом в `en.json`.
  Так не бывает ключей, существующих только в переводе.
- **Пустая строка — законное значение,** отсутствующий ключ — нет. Если фразы
  на английском пока не будет, оставьте `""`, а не удаляйте ключ.
- **`&` и кавычки экранируются сами.** Писать `&amp;` в словаре не нужно —
  получится `&amp;amp;`.
- **Периоды и даты — тоже текст.** «Сентябрь — Декабрь 2025» переводится.
- **Куски разметки проходят через словари наравне с шаблоном:** их вклеивает
  сам загрузчик, до подстановки текстов. Поэтому `{{ header.cv }}` внутри
  `headerbar.html` переводится, а вот текст `footerbar.html` до сих пор
  русский — просто потому, что его ещё не вынесли в словарь.
- **Логики в шаблоне нет.** Если нужен другой текст — это другой ключ, а не
  условие. Если нужен другой вид — это другой тип блока, а не флаг.
